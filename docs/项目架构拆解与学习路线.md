# 一、项目架构拆解（基于源码 + README）

「项目拷打 副本」文档中 DoVideoAI 的简历八大亮点与 README 的"四层能力"完全对应，以下按源码验证后的实际架构来讲。

## 1. 定位与分层

DoVideoAI 是**面向长视频内容理解的 Video Agent 平台**，本质是把"长耗时、高资源消耗、成本敏感"的视频解析做成一条**异步任务流水线**：

```
Vue3 工作台 (Vite/SSE/Marked)
    │ 分片上传 / SSE 订阅
Spring Boot 3.5.9 API (Java 21 + Undertow + MyBatis-Plus + Flyway)
    │ 202 Accepted 立即返回
RocketMQ 5.3.4 ──► 消费者 Worker（死信 topic + 失败任务表重投递）
    │
    ├─ VideoContext 双分支：FFmpeg 音频切片→ASR ╲ 并行 ╱ 关键帧→OCR（感知哈希去重）
    ├─ 混合检索：分段摘要 + 关键词 + Qdrant 向量召回（BGE-M3）
    ├─ AgentLoop：Planner → Executor → Critic（最多 2 轮，预算护栏）
    └─ Checkpoint：MySQL 真源 + Redis 热缓存，断点恢复
MySQL 8 / MinIO / Qdrant / Redis 7.4 (Redisson)
```

## 2. 技术栈与对应源码

| 模块 | 技术 | 源码落点 |
|---|---|---|
| 任务链路 | RocketMQ 异步削峰 + 死信重投 | `server/src/main/java/com/example/server/consumer/VideoAnalysisConsumer.java`、`service/AnalysisDispatchService.java` |
| 分布式锁 | Redisson：内容指纹锁 + 分片合并锁 | `service/AiService.java`（L160）、`service/ChunkUploadService.java`（L115） |
| 实时推送 | SseEmitter + Redis 事件桥（替代轮询，文档里"~~轮询~~"被划掉就是它） | `service/TaskEventService.java` |
| 成本护栏 | 用户级 + 全局令牌桶限流、指数退避重试 | `service/AnalysisDispatchService.java`（L132） |
| Agent | LangChain4j + DeepSeek，Planner/Executor/Critic 受控循环 | `service/AgentLoopService.java` |
| RAG | Qdrant + BGE-M3 Embedding + 关键词混合检索，降级策略 | `service/QdrantVectorStore.java`、`service/VideoEvidenceRetrievalService.java` |
| 认证 | PBKDF2 加盐哈希 + 不透明 token 存 Redis（**不是 JWT**） | `service/AuthService.java` |
| 中间件编排 | Docker Compose：MySQL/Redis/Qdrant/MinIO/RocketMQ | `docker-compose.yml`、`server/src/main/resources/application.properties` |

## 3. 飞书文档的面试总结结构

- **DoVideoAI 部分**（占全文 95%）：RocketMQ 异步化、Redisson+WatchDog+MD5 内容级去重、分片上传断点续传、Redis 令牌桶限流、指数退避重试、RAG 全链路（分块/Embedding/BM25/RRF/Rerank/记忆压缩），外加"MQ 消费者开发规范六步流程"。
- **CityHub 部分**：只有简历七条亮点（Lua 秒杀、MQ 削峰、击穿穿透、补偿重试、滑动窗口限流、延迟关单、乐观锁），**没有问答**——这正好是学习清单已经覆盖的范围。

# 二、学完已列清单后，还缺什么

已列清单（缓存/分布式锁/秒杀/MQ/RocketMQ/延迟关单/幂等防刷/多级缓存）**完整覆盖了 CityHub 的所有亮点**，但对照 DoVideoAI 的源码和面试文档，缺口非常清晰——**几乎全部集中在 AI 工程侧，这正是文档作者说"备战秋招转 AI 的重点"**。

## 第一优先级：AI 应用工程（DoVideoAI 的核心差异化，当前清单 0 覆盖）

1. **RAG 全链路**——文档里已给出完整答案链：分块策略（递归分块）→ Embedding 选型（BGE-M3/中文/维度/成本）→ 混合检索（BM25 补向量短板，RRF 融合不可比分数）→ Rerank（Cross-Encoder vs Bi-Encoder）→ 引用对齐与幻觉抑制。项目落点就是 `QdrantVectorStore.java`，建议照源码把这条链复述一遍。
2. **Agent 工作流设计**——Planner-Executor-Critic 受控循环为什么要有 Critic、为什么限 2 轮、证据时间戳怎么校验（`AgentLoopService.java` L206），以及 Function Calling、ReAct、结构化输出（JSON Schema）这些通用概念。
3. **LLM 基础八股**——文档里已有 Transformer、token、Temperature/top_p、上下文窗口与记忆压缩（滑动窗口→摘要机制）。这是 AI 项目面试的入场券。
4. **Agent 评测**——项目里有 `OfflineAgentEvaluationRunner.java` + `golden-video-tasks.json` 离线评测（对应文档 Todo 里未勾选的"Rubric 产物评测"），能讲出"怎么量化 Agent 产出质量"是稀缺加分项。

## 第二优先级：清单没覆盖、但源码在用、面试会追问的后端点

5. **SSE 服务端推送**——为什么弃轮询用 SSE、对比 WebSocket/长轮询、断线重连。落点 `TaskEventService.java`。
6. **死信队列 + 失败任务补偿**——`video-analysis-dead-topic` + `FailedAnalysisTask` 表 + 管理接口重投递。RocketMQ 学到"死信"概念后，这里是现成实战案例，CityHub 的"MQ 补偿重试"可以直接对齐着讲。
7. **线程池隔离与参数**——ASR/OCR 独立有界线程池并行（`config/ThreadPoolConfig.java`）：核心/最大线程数、拒绝策略、故障隔离思想。黑马课只教了基础用法。
8. **大文件上传与对象存储**——MinIO、5MB 分片、Redis 记分片状态、合并锁、MD5 内容指纹去重。这是 DoVideoAI 简历亮点，当前清单里完全没有。
9. **认证方案取舍**——项目用"不透明 token + Redis 会话"而非 JWT，要能讲 session vs JWT 的取舍（主动失效/登出/多端踢人），这比背 JWT 八股更能体现思考。

## 第三优先级：工程素养（锦上添花）

10. **Flyway 数据库版本管理**（V1~V3 迁移脚本）、优雅停机、Undertow vs Tomcat 选型——一句话级别的了解即可。
11. **可观测性雏形**——`service/AgentTelemetry.java` 的 traceId/预算用量追踪，往"我关注线上问题定位"上靠。

## 两个提醒

- **别把清单一股脑套到 DoVideoAI 上**：多级缓存（Caffeine+Redis）、延迟关单、秒杀 Lua 是 CityHub 的亮点；DoVideoAI 没有这些，它的关键词是**异步化、幂等去重、成本护栏、RAG、Agent**。面试时两个项目要讲不同的故事。
- **文档作者自己提醒**：Redisson/RocketMQ 在低并发下"为选型而选型"，面试官追问时你要主动给出"当前量级用 JVM 锁/线程池更合理，引入 MQ 是为演进而非炫技"这类选型反思——这比背方案更加分。
